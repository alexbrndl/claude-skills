# Style DNA template

A separate art-direction document, created once per product/blog/series and reused for every image. It is the single source of truth that keeps a set of illustrations visually consistent. Fill in every section; vague rules produce inconsistent output.

When the illustrations represent a real brand, ground this document on the brand's actual assets (logo, product renders, UI screenshots, brand palette) before inventing anything. The style DNA describes how those assets are rendered, not a generic look.

---

## Visual rules

State the non-negotiable rendering rules. Keep them measurable.

- **Rendering style:** the medium and feel (e.g. flat hand-drawn line art / soft 3D / cut-paper collage). Pick one and never mix.
- **Line quality:** weight, regularity, stroke treatment (e.g. thin, slightly wobbly pen lines, no heavy vector outlines).
- **Whitespace minimum:** the floor for empty space (e.g. at least 35% blank, main subject 40-60% of the canvas). A number, not "lots of room".
- **Canvas ratio:** fixed aspect ratio for the series (e.g. 16:9, 1:1, 4:5). Do not vary it within a series.
- **Background:** the fixed background treatment (e.g. pure white, no gradient, no shadow, no texture).
- **Annotation budget:** max number and length of text labels per image (e.g. at most 5-8 labels, each 2-8 words).

## Semantic color code

Assign each color **one fixed role** and never reuse a color for a different meaning across the series. This is what makes a viewer read the set as one language. Keep the palette small.

| Color | Role | Use for |
|---|---|---|
| Black | **structure** | main line art, frames, the recurring element, primary objects, primary text |
| Orange | **flow** | main path, arrows, A→B movement, automation direction |
| Red | **alert** | warnings, problems, key results, the one thing to notice |
| Blue | **secondary state** | secondary notes, system/internal state, second-layer explanation |

Rules:
- Restraint over coverage: not every color must appear in every image. Prefer fewer.
- A color may never carry two meanings in the same series.
- If the brand palette differs, remap the *roles* onto the brand colors but keep one-role-per-color.

## Must

- Fixed canvas ratio across the whole series.
- One image expresses exactly one core idea, structure, state, or metaphor.
- Honor the whitespace minimum and the annotation budget.
- Express structure through the drawing itself, not by labeling the structure type on the image.

## Never

- No title in a corner naming the diagram type ("Workflow", "Architecture", "Common pitfalls").
- No formal flowchart, slide deck, or dense explainer look.
- No gradients, shadows, paper texture, or busy backgrounds (unless the DNA explicitly calls for them).
- No off-palette colors and no color used outside its assigned role.
- Do not explain every node; leave the obvious implied.

## Recurring element (optional)

A single recurring character, mascot, or motif that appears across the series and ties it together. Optional, but if used it must be defined precisely and must participate in the core action of each image, never sit beside it as decoration.

- **Form:** how it looks (shape, color, distinguishing features).
- **Behavior:** what it does (it performs the idea, it does not pose).
- **Never:** how it must not be drawn (e.g. not overly cute, no elaborate costume, never just watching from a corner).

## Filled example

**Visual rules** — Flat hand-drawn black line art; thin slightly wobbly pen lines; at least 35% blank space, subject 40-60% of canvas; 16:9; pure white background; at most 5-8 labels of 2-8 words.

**Semantic color code** — Black = structure (line art, objects, primary text). Orange = flow (arrows, the main path). Red = alert (the one warning or result). Blue = secondary state (internal/system notes). Blue is optional per image.

**Recurring element** — A small solid-black creature with white dot eyes and thin legs, deadpan and serious. It performs the core action of every image (carrying, pulling, sorting, holding a sign); it is never a decorative bystander.
